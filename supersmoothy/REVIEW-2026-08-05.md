# SuperSmoothy all-platform audio-device review — 2026-08-05

Working notes for the cross-platform hardening pass. The macOS
(`juce_CoreAudio_mac.cpp`) findings are FIXED (see SUPERSONIC-CHANGES.md);
the rest are findings-with-citations for a machine that can compile the
target platform — do not fix blind (no MSVC/Linux toolchain on the
reviewing machine).

## Defect classes (proven on macOS, hunt everywhere)

1. **Capacity vs delivered frames**: intermediate buffers sized from a
   negotiated `bufferSize` while the driver delivers (or the code later
   trusts) a different count. macOS instance was ASan-proven heap
   corruption (#3555).
2. **Unsynchronised renegotiation**: rate/buffer members mutated by
   notification paths without re-allocating / without the callback lock.
3. **Teardown races on notification threads**: driver/OS callbacks holding
   raw pointers to objects being destroyed on another thread;
   deregistration APIs that don't drain in-flight callbacks. Fix pattern:
   `LiveInternalRegistry` fence (currently local to juce_CoreAudio_mac.cpp
   — hoist to a shared header when a second platform needs it).
4. **Deferred-restart timers** on the message thread racing teardown on
   the embedder's threads (SuperSonic destroys devices off the message
   thread; stock JUCE assumes message-thread destruction).

## WASAPI (`juce_WASAPI_windows.cpp`) — class-3 findings FIXED (blind)

- FIXED: `SessionEventCallback` raw-`owner&` bodies and
  `ChangeNotificationClient::notify()` now run under the shared
  `LiveObjectRegistry` fence (`juce_LiveObjectRegistry.h`, extracted from
  the CoreAudio fix). Authored blind on macOS — Windows CI compile
  arbitrates; runtime validation on real Windows hardware still wanted
  (device unplug + default-device flip during teardown).
- NOT yet audited: `deviceSampleRateChanged` restart path for class 2;
  the capture/render buffer sizing for class 1 (WASAPI reads per-packet
  frame counts from the driver, so class 1 is less likely by shape).

## ALSA (`juce_ALSA_linux.cpp`) — briefly surveyed, lower risk

- Device-owned `ALSAThread` with `stopThread(6000)` join at close (~658):
  teardown is a real join, so class 3/4 exposure is low.
- `scratch.ensureSize(numSamples * channels)` per call (319, 356): sized
  from the actual per-call count, so class 1 exposure is low.
- Audit remaining: `bufferSize = newBufferSize` (509) renegotiation path
  (class 2); the close-ordering comment at ~643 documents a known
  fragility worth a second read.

## Residual macOS items (known, accepted for now)

- `audioIOProc` raw `CoreAudioInternal*` cookie: an IOProc invocation that
  began before `AudioDeviceDestroyIOProcID` and is blocked on
  `callbackLock` can in principle resume against a dying internal. Decade
  of JUCE field history without a report; revisit if a crash ever lands
  there.
- `LiveInternalRegistry::ifLive` holds one global lock across fenced
  bodies (including a device reopen inside a timer body). Contention is
  restart-rate only; fine for now, split per-instance if it ever shows up
  in traces.
